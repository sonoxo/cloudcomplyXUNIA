# NXYZ Cloud v1

NXYZ Cloud v1 is a local-first private application cloud. It combines the NXYZ control plane, scheduler, rootless Podman workers, published services, local data services, private OCI/Git infrastructure, AI hooks, backups, and a multi-node private mesh.

## One-time update

```bash
git pull --ff-only
cd nxyz-cloud
make install-cli
hash -r
nxyz
```

## Daily commands

```bash
nxyz status

```

## Run a reachable web app

NXYZ web workloads declare their container port. The worker publishes an ephemeral host port and reports the endpoint back to the control plane.

```bash
nxyz deploy image web nginx:alpine 250 128 80 /
nxyz services
nxyz service open web
```

Git deployments use the same flow:

```bash
nxyz deploy git myapp https://github.com/OWNER/REPO.git 500 512 3000 /health
```

The flow is:

```text
Git / OCI image
   -> NXYZ scheduler
   -> healthy worker
   -> rootless Podman container
   -> dynamic host port
   -> endpoint + health state
   -> dashboard / service API / NXYZ reverse proxy
```

## Private mesh

On the controller PC:

```bash
nxyz mesh enable
nxyz mesh token
```

On another authorized NXYZ PC:

```bash
nxyz mesh join http://CONTROLLER-LAN-IP:8080 TOKEN
```

Joined workers do not start competing local controllers. They register against the selected controller and contribute their CPU, RAM, available disk, and workload execution capacity.

Local-only binding is the default. Mesh mode explicitly changes the controller/service bind to the LAN and uses the persisted cluster token for mutation APIs.

## Dedicated server / 1-TB data drive

For a Linux backup PC, mount the SSD/HDD first and make the directory writable by the user running NXYZ. Then:

```bash
nxyz server install /mnt/nxyz
nxyz server status
```

The installer:

- makes the selected path the NXYZ persistent data root;
- puts rootless Podman graph storage under that data root;
- enables private mesh controller mode;
- installs a user-level `nxyz-cloud.service`;
- restarts NXYZ if a managed server child exits;
- leaves persistent data untouched if the service is uninstalled.

For boot-before-login operation, Linux may require one administrative command:

```bash
sudo loginctl enable-linger "$USER"
```

## Capacity model

NXYZ has no artificial software quota, but it does not manufacture hardware. Cluster capacity is the sum of the resources contributed by the connected nodes. Adding machines or larger disks increases the resource pool.

A single 1-TB server is therefore approximately a 1-TB raw storage substrate minus filesystem, Podman, application, database, replication, and backup overhead. Real usable capacity is always reported with `nxyz storage status` rather than advertised as unlimited.

## Current trust boundary

NXYZ v1 is a private-cloud foundation, not a claim of AWS/GCP-scale infrastructure. Public DNS, public Internet ingress, globally redundant controllers, cross-site replicated object storage, and automatic public certificate issuance depend on external networking, additional machines, or infrastructure that cannot be created from software alone. The v1 default remains private and local/LAN-first.
